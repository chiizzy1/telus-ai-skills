# Breadth and Direction

Use with `../SKILL.md`. The guideline's hardest calls are not about topic, they are about **how broad each side is and which way the pair runs**. The same two concepts can be Acceptable in one direction and Bad in the other, and the guideline says so outright.

Read this file whenever one side is broader than the other. That covers most Bad ratings on this task.

## Direction is not symmetric

The keyword is what the advertiser bought. The expansion is what the user typed. The question is whether the advertiser's intent covers the user's, and that is a one-way test.

The guideline's clearest statement of this is at `learning games for kids` → `toddler games`, rated **Acceptable**, with the note: *"The keyword is generic enough to share the same intent of kids games where kids also includes toddlers. **Reverse would not be true.**"*

And the reverse is in the Bad table: `Toddler games` → `Learning games for kids` is **Bad**, because *"keyword is specific to toddler and expansion is specific to kids which is broader than toddler intent"*.

Same two phrases. Opposite ratings. **Always check which side is the keyword before rating.**

## Broad keyword to specific expansion

Usually **Acceptable**, when the specific side is a genuine instance of the broad side's intent.

| Pair | Rating | Why |
|---|---|---|
| `multiplayer` → `fortnite` | Acceptable | Fortnite is a multiplayer game |
| `learning games for kids` → `toddler games` | Acceptable | Toddlers are kids |
| `Great Indian festival` → `Amazon` | Acceptable | The festival is Amazon India's sale event |
| `Eight year old coloring games` → `Colouring book for girls` | Acceptable | Both are children's colouring. Would have been Bad if the expansion were colouring for adults or teenagers |
| `Simple scorecard` → `My easy golf scorecard` | Acceptable | The keyword's intent is generic, so a golf scorecard still serves it |

The guideline's own annotations on the last two show the test: it asks what would have broken the pair. `Simple scorecard` works *because* the keyword is generic; had the keyword been `scorecard for children`, the intent would have been specific and a golf scorecard would not have served it.

## Specific keyword to broad expansion

Usually **Bad**. A narrow advertiser intent is not served by a broad user query.

| Pair | Rating | Why |
|---|---|---|
| `Shooting games` → `Online games` | Bad | The keyword is very specific and the expansion is a generic query |
| `keto` → `cookbook` | Bad | A specific diet against a generic term |
| `Toddler games` → `Learning games for kids` | Bad | Kids is broader than toddler |
| `Toddler games` → `Learning games for teens` | Bad | Not broader, simply a different age |

**The exception that is not an exception:** `google maps` → `google` is **Good**, and `scanner pro` → `scanner app` is **Acceptable**. Both look like specific-to-broad. They are not, because the broad side still carries the original intent: `google` is the parent brand of `google maps`, and `scanner app` is a request for the very thing `scanner pro` is. Compare `keto` → `cookbook`, where a cookbook is not a keto thing.

The test: **does the broader term still point at what the keyword wanted?** If yes it survives. If the broader term merely contains it among many other things, it is Bad.

## The empty keyword rule

Some keywords are so broad they carry no intent at all. Any specific expansion against them is **Bad**, whatever the topic.

| Pair | Rating |
|---|---|
| `App` → `Netflix` | Bad |
| `Free` → `Facebook` | Bad |
| `Free apps for iPhone` → `Instagram` | Bad |
| `Download app` → `Snapchat` | Bad |

The guideline's reasoning is identical each time: both sides share the intent of *apps*, but the expansion's intent is very specific to one service, so they do not share intent and meaning.

This is Bad category 1's second clause: *a generic brand keyword that expands to a specific expansion leading to misaligned intent*. Do not confuse these with the Acceptable broad-to-specific cases above. `multiplayer` names a real property that Fortnite has. `Free` names nothing.

## Sibling terms under one parent

Two specific things under one broad umbrella are **Bad**, because neither contains the other.

| Pair | Rating | Shared parent |
|---|---|---|
| `cooking games` → `shooting games` | Bad | games |
| `Adventure games` → `Horror games` | Bad | games |
| `shooting games` → `toddler games` | Bad | games |
| `picture editor` → `video editor` | Bad | editing apps |
| `photo collage` → `Flyer Maker` | Bad | design apps |
| `Amazon fresh grocery` → `Amazon Alexa` | Bad | Amazon |
| `google maps` → `google translator` | Bad | Google |
| `kindle` → `alexa` | Bad | Amazon |

A shared category is never enough. The guideline repeats this in almost every Bad explanation: *"even though both are about games"*, *"despite both products belonging to amazon"*, *"even though both are offerings are from the same brand"*.

Contrast with Acceptable 4, where two different phrases point at **one** goal (`diet tracker` → `calorie counter`). Siblings point at two.
